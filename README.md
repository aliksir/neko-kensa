# neko-kensa

Code quality inspector powered by [code-graph](https://github.com/nicolo-ribaudo/code-graph) MCP server's SQLite database. Zero dependencies.

neko-kensa queries the `graph.db` generated by code-graph's `index_repository` command and provides dead-code detection, circular dependency analysis, structural linting, repository statistics, and interactive dependency graph visualization -- all without installing any npm dependencies.

## Installation

```bash
npm install -g neko-kensa
```

Or run directly:

```bash
npx neko-kensa --help
```

## Prerequisites

neko-kensa requires a `graph.db` file generated by [code-graph](https://github.com/nicobailon/code-graph). It does **not** analyze code on its own -- it reads the pre-built SQLite database.

1. **Node.js >= 22.0.0** (uses `node:sqlite` built-in module)
2. **Add code-graph as an MCP server** (`.mcp.json` or Claude Code settings):
   ```json
   {
     "mcpServers": {
       "code-graph": {
         "command": "npx",
         "args": ["-y", "code-graph-mcp"]
       }
     }
   }
   ```
3. **Run `index_repository`** in Claude Code to generate `graph.db`:
   ```
   Use the index_repository tool to index /path/to/your/repo
   ```
   This creates `~/.code-graph/graph.db` which neko-kensa reads (read-only).
4. **Run neko-kensa** commands as usual.

## Commands

| Command | Description | Similar to |
|---------|-------------|------------|
| `dead`  | Detect unreachable files from entry points | [Knip](https://knip.dev/) |
| `deps`  | Detect circular dependencies and rule violations | [dependency-cruiser](https://github.com/sverweij/dependency-cruiser) |
| `stats` | Show repository statistics (files, symbols, languages) | -- |
| `graph` | Generate interactive HTML dependency/class/call graph | [Astah](https://astah.net/) |
| `lint`  | Structural code quality checks | [Biome](https://biomejs.dev/) |

## Usage

```
neko-kensa dead  [path] [--entry <file>...]  [--json] [--db <path>]
neko-kensa deps  [path] [--rules <file>]     [--json] [--db <path>]
neko-kensa stats                             [--json] [--db <path>]
neko-kensa graph <type> [--out <file>] [--dir]        [--db <path>]
neko-kensa lint  [--rules <file>]            [--json] [--db <path>]
```

### Options

| Option | Applies to | Description |
|--------|-----------|-------------|
| `--entry <file>` | `dead` | Specify entry point files (repeatable) |
| `--rules <file>` | `deps`, `lint` | Path to rules file (default: `.neko-kensa.json`) |
| `--json` | `dead`, `deps`, `stats`, `lint` | Output as JSON |
| `--out <file>` | `graph` | Write HTML to file instead of stdout |
| `--dir` | `graph deps` | Aggregate dependency graph by directory |
| `--db <path>` | all | Path to graph.db (default: `~/.code-graph/graph.db`) |

## Examples

### Dead code detection

```bash
# Auto-detect entry points from package.json
neko-kensa dead .

# Specify entry points manually
neko-kensa dead . --entry src/index.mjs --entry src/cli.mjs

# JSON output for CI
neko-kensa dead . --json
```

### Circular dependency detection

```bash
# Detect cycles
neko-kensa deps

# With custom rules
neko-kensa deps --rules .neko-kensa.json
```

### Dependency rules (`.neko-kensa.json`)

```json
{
  "rules": [
    {
      "name": "no-ui-in-core",
      "type": "forbid",
      "from": { "pathPattern": "^src/core/" },
      "to": { "pathPattern": "^src/ui/" },
      "message": "Core modules must not depend on UI modules",
      "severity": "error"
    }
  ],
  "lint": {
    "large-file": { "max": 500 },
    "high-fan-out": { "max": 20 }
  }
}
```

### Repository statistics

```bash
neko-kensa stats
# Repository: /path/to/repo
# Files: 142
# Symbols: 1,203
# Dependencies: 856
# Circular dependencies: 2
#
# By language:
#   TypeScript  98 files
#   JavaScript  31 files
#   CSS         13 files
```

### Interactive graph visualization

```bash
# File dependency graph (HTML)
neko-kensa graph deps --out deps.html

# Directory-level dependency graph
neko-kensa graph deps --dir --out deps-dir.html

# Class inheritance hierarchy
neko-kensa graph class --out class.html

# Function call graph
neko-kensa graph calls --out calls.html
```

The generated HTML is self-contained with an interactive canvas (pan, zoom, hover tooltips). No external dependencies required to view.

### Structural lint

```bash
neko-kensa lint
# [large-file] (3 issues)
#   W src/generated/parser.ts: 1204 lines (max: 300)
#   W src/utils/helpers.ts: 450 lines (max: 300)
#   ...
#
# [high-fan-out] (1 issues)
#   W src/index.ts: 22 imports (max: 15)
#
# Summary: 4 issues (0 errors, 4 warnings)
```

#### Lint rules

| Rule | Default | Description |
|------|---------|-------------|
| `large-file` | max: 300 lines | Files exceeding line count threshold |
| `high-fan-out` | max: 15 imports | Files with too many outgoing dependencies |
| `high-fan-in` | max: 20 dependents | Files depended on by too many others |
| `deep-inheritance` | max: 5 levels | Classes with deep inheritance chains |
| `many-symbols` | max: 30 symbols | Files exporting too many symbols |
| `unresolved-import` | -- | Imports that could not be resolved |

All thresholds are configurable via `.neko-kensa.json`.

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | No issues found |
| 1 | Issues detected (dead files, cycles, lint violations) |

## Architecture

```
neko-kensa
  |-- src/
  |   |-- cli.mjs    Entry point & argument parsing
  |   |-- db.mjs     Read-only SQLite wrapper for graph.db
  |   |-- dead.mjs   Dead code detection (BFS reachability)
  |   |-- deps.mjs   Cycle detection (Tarjan's SCC) & rule checking
  |   |-- stats.mjs  Repository statistics aggregation
  |   |-- graph.mjs  Interactive HTML graph generation (force-directed layout)
  |   |-- lint.mjs   Structural quality checks
  |-- tests/         node:test based test suite
  |-- package.json
```
